RP2040 / RP2350 emulator in the browser

One bench, three cores, two chips.

Bramble emulates Raspberry Pi's RP2040 and RP2350 microcontrollers well enough to boot real firmware — littleOS shells, MicroPython, and bare-metal peripheral demos — natively and in the browser through WebAssembly.

426 sweep-locked tests Cortex-M0+ / M33 / Hazard3 RV32 native + WASM, same sources

What this project is

Bramble is a from-scratch emulator for the RP2040 (dual Cortex-M0+) and the RP2350 (dual Cortex-M33 or dual Hazard3 RISC-V, switched at boot). It loads UF2 and ELF images, models flash, SRAM, the boot path, interrupts, SysTick, and the full peripheral set, and it runs unmodified firmware: the same littleos.uf2 or MicroPython build you would flash onto a Pico.

The emulation core is a port of Night-Traders-Dev/Bramble (MIT), extended here with M33 and RISC-V cores, VFP single-precision, a double-precision unit, and host-threaded dual-core execution. The WebAssembly build compiles those exact sources with Emscripten, so the browser bench and the native binary agree instruction for instruction.

How it is put together

Three layers, each replaceable without touching the others:

  1. Cores. An O(1)-dispatch Thumb engine shared by M0+ and M33 (M33 adds Thumb-2, BASEPRI, its own CPUID, VFP/DCP floating point on top), plus a separate Hazard3 RV32IMAC engine with Zba/Zbb/Zbs/Zcb/Zcmp extensions, CSRs, CLINT, and semihosting.
  2. Memory and peripherals. A routed bus (flash/XIP, SRAM, ROM function table, NVIC, SysTick, GPIO, UART, SPI, I2C, PWM, ADC, DMA, PIO, USB, clocks, watchdog, RTC), RP2350 additions (520 KB SRAM, 32 KB ROM, TIMER1, PIO2, QMI, OTP, BOOTRAM, POWMAN, TICKS), and device models on top (CYW43 WiFi/BT, W5500 Ethernet, SD/eMMC, sensors).
  3. Hosts. A native CLI for speed and scripting, and a WASM embedding (bramble_step + UART/GPIO/memory exports) that the browser bench, a Node CLI, GDB-over-WebSocket, and virtual-network bridges all share.
firmware.uf2 ──▶ loader ──┬──▶ Cortex-M0+ ──▶ RP2040 bus ──▶ peripherals ──▶ host │ ├──▶ Cortex-M33 ──▶ RP2350 bus ──▶ peripherals ──▶ host │ └──▶ Hazard3 RV32 ─▶ RP2350 bus ──▶ peripherals ──▶ host │ └── arch from UF2 family ID or picobin IMAGE_DEF

One loader, three cores, one peripheral set per chip family. The host is either the native CLI loop or the browser frame loop.

The three cores

Cortex-M0+ — the RP2040 core

Full Thumb-1 plus BL, MSR/MRS, barriers, NZCV flags, tail-chaining and late-arriving interrupts, PRIMASK/FAULTMASK. Boots through boot2 and the ROM table like real silicon. This is the core behind the classic Pico demos and the RP2040 MicroPython build.

Cortex-M33 — the RP2350 ARM core

Thumb-2 engine reuse with M33 CPUID, BASEPRI masking, IT-block handling, single-precision VFP and a double-precision unit, running against the RP2350 memory map. Boots littleOS to a shell with a working Sage evaluator. TrustZone (SAU attribution + TT), an 8-region PMSAv8 MPU with faults, the ARMv7-M DSP scalar subset, and the MVE-Helium integer vector subset are all modeled (single Secure world); vector FP/complex beats remain future work.

Hazard3 RV32 — the RP2350 RISC-V core

A clean-room RV32IMAC implementation with the Zba/Zbb/Zbs/Zcb/Zcmp bit-manipulation and code-size extensions, machine CSRs, CLINT timer and software interrupts, dual-hart launch through the SIO mailbox, and ebreak semihosting. Boots the RISC-V littleOS build to an interactive shell.

RP2350A or RP2350B? Both, as far as software can tell. A and B are package variants of the same die: 30 versus 48 GPIO pins (and 4 versus 8 ADC channels, 16 versus 24 PWM channels). Bramble models the full 48-pin die, so firmware written for either package runs; pins 30–47 simply stay quiet on A-package builds.

What runs on it

  • littleOS interactive shells on all three cores, including Sage print(6*7) evaluation.
  • MicroPython REPLs over USB CDC (RP2040 and RP2350 builds), tested with banner plus print(6*7) → 42.
  • Forty-plus bare-metal self-tests covering every peripheral, plus WiFi scan/ping/join, BLE advertise and GATT (RV32 reference path), IPv6 ping, dual-core demos, and in-tree W5500 DHCP + HTTP-client guests on all three cores.
  • Live MicroPython on a Pico W build: WiFi station, BLE active(True) with the full HCI bring-up trace, advertising, and GATT register/write/read.

How to check any claim

Every statement on this page traces to something runnable: ctest --test-dir build for the 426 unit tests, node test-wasm.js for the browser equivalents, the UF2 dropdown on the bench page for firmware, and the support tables for the per-feature, per-core breakdown with remarks.
